# 弹窗统一规范 & UI 设计评审

> 范围：AI Mac Cleaner 全部 11 个 `.sheet` 弹窗 + 主界面外壳。
> 目标：统一关闭/取消按钮的位置与语义，消除"每次都要重新找关闭键"的割裂感；顺带修掉几处离谱的离谱不一致。
> **实施状态（2026-08-10）**：已落地。新增 `UI/SheetComponents.swift`（`SheetHeader` / `SheetActionBar` / `SheetCloseButton` / `blanketDismiss` 修饰符）；11 个弹窗的关闭键统一沉到 `SheetActionBar` 右下；只读弹窗（结果/预览/反馈记录/长期记忆/卸载历史/macOS 工具/关于）支持 **Esc 关闭 + 点卡片四周空白关闭**；输入类（反馈表单/模型配置）与危险确认（卸载/删除/FDA）关闭空白关闭、加 `interactiveDismissDisabled` 与「未保存就关」二次确认；反馈主按钮补 `.tint(Theme.accent)`。

---

## 一、现状问题（已逐文件核对）

同一类"关闭 / 取消 / 完成"动作，目前散落在**三个不同角落**：

| 位置 | 弹窗 | 问题 |
|------|------|------|
| 右上角（header 内） | 结果页、反馈预览、反馈记录、长期记忆、卸载历史、模型配置（取消） | 共 6 个，纯阅读类的关闭全挤在右上角 |
| 右下角（footer 内） | macOS 工具、关于 | 另 2 个阅读类却放在右下角 |
| 左下角（footer 内） | FDA 引导（取消在最左）、确认/反馈（复制/预览占左侧导致取消偏左） | 取消键被推到最左，与上面两类对不上 |

**结论**：阅读类弹窗的"关闭"键在 6 个里是右上、2 个里是右下；含操作的弹窗里"取消"还被挤到左下。用户每次开不同弹窗都得重新定位关闭键——这就是你感觉到的"怪"。

## 二、统一规范（建议采用）

### 2.1 两种弹窗骨架

- **只读弹窗（Reader）**：结果页、反馈预览、反馈记录、长期记忆、卸载历史、macOS 工具、关于。
  - header 只放标题（+ 可选副标题），**不放关闭按钮**。
  - footer 右侧放**唯一**的「关闭」。
- **操作弹窗（Action）**：模型配置、FDA 引导、确认卸载、反馈表单。
  - footer 左侧放辅助动作（预览 / 复制全部路径 / 打开系统设置）。
  - footer 右侧放「取消」+ 主操作，**主操作永远最右**，取消紧贴其左。

### 2.2 按钮秩序（macOS HIG 对齐）

```
[ 左侧辅助动作 ................. ] [ 取消 ] [ 主操作 ]
```
- 主操作（保存 / 提交 / 卸载 / 我已授权）：`borderedProminent` + `.tint(Theme.accent)`。
- 真正不可逆的（清空历史、彻底删除）：`.tint(Theme.destructive)`。
- 只读弹窗的单一关闭键：普通 `bordered` 即可，置右下。

### 2.3 标签统一

- 所有只读弹窗统一用**「关闭」**，不再混用 关闭/完成/Done。
- 「完成」只保留给"任务做完才出现"的流（如「问 AI」对话结束），不用于普通面板。
- 顶部 header **不再出现关闭按钮**，消除重复入口（现在结果页/预览/记录/记忆/历史既无底部关闭、又无统一感）。

### 2.4 落地手段

抽两个共享组件，全量替换手写 header/footer：
- `SheetHeader(title:subtitle:)` —— 标题 + 可选副标题，右下不再塞按钮。
- `SheetActionBar(leading:trailing:)` —— 左辅助 / 右按钮组，统一内边距与分隔线。

当前只有 `AIModelSettingsSheet` 用了一个 `PageHeader` 雏形，其余 10 个都是各写各的 HStack，正是混乱的根源。

### 2.5 退出交互：点空白关闭 + Esc（按弹窗类型分层）

点空白处关闭（click-outside-to-dismiss）确实比"满屏找关闭键"方便，但**不能一刀切**——对带用户输入的弹窗，误点空白会丢掉用户刚填的内容，比"找不到关闭键"更糟。所以按类型分层：

| 弹窗类型 | 代表 | 点空白关闭 | Esc | 说明 |
|----------|------|:---:|:---:|------|
| **只读** | 结果页 / 预览 / 记录 / 长期记忆 / 卸载历史 / macOS 工具 / 关于 | ✅ 开 | ✅ 开 | 无数据风险，怎么方便怎么来 |
| **输入** | 反馈表单 / 模型配置 | ❌ 关 | ⚠️ 脏数据拦截 | 点空白 / 按 Esc 若有未保存内容，**先拦一道确认**（"放弃未保存的更改？"），避免误丢 |
| **危险确认** | 确认卸载 / 确认删除 | ❌ 关 | ✅ = 取消 | 空白区域不是按钮，误点不应触发任何动作；Esc 默认等同取消，安全 |

**为什么 macOS 上更推荐 Esc 而非点空白**：
- macOS 的 sheet 原生不响应"点空白关闭"，要做只能自己挂手势 / 全屏透明层——属于非原生行为，容易和窗口拖拽、列表选中冲突。
- 而 **Esc 关闭是 macOS 原生惯例**（有取消/完成按钮的 sheet 按 Esc 即关），键盘可达、不会误触、且不丢数据（输入类我们再加脏拦截）。
- 结论：**Esc 作为全量"便捷退出"主力；点空白仅给只读弹窗锦上添花；输入/危险类不开放点空白。**

**实现要点**：
- 输入类弹窗用 `.interactiveDismissDisabled(true)` 关掉系统默认的轻扫/点外关闭（防止意外），再自己用 `onExitCommand` / `keyboardShortcut(.cancelAction)` 处理 Esc。
- 脏数据拦截：维护一个 `isDirty` 状态，Esc / 点关闭时若 `isDirty` 为真，先弹二级确认再 dismiss。
- 只读弹窗的点空白：在 sheet 内容最外层叠一层透明 `Color.clear` + `onTapGesture { dismiss() }`，并把内容卡片 `contentShape` 设为不响应，避免误关内容区。

## 三、设计师 UI 评审（额外发现）

1. **【必修】反馈表单主按钮掉色**：`FeedbackSheet` 的「提交反馈」用了 `.buttonStyle(.borderedProminent)` 却**没设 `.tint`**，渲染成系统蓝，而全 app 其他强调按钮都是 Petrol Blue（`Theme.accent`）。一眼就能看出"这不是我们家的按钮"。→ 补 `.tint(Theme.accent)`。

2. **【必修】弹窗 chrome 重复**：11 个弹窗里约 100 行 header/footer 布局是复制粘贴的。抽 `SheetHeader` / `SheetActionBar` 后既统一位置、又减少维护面。

3. **【建议】字号阶梯太碎**：代码里出现 9 / 9.5 / 10 / 10.5 / 11 / 11.5 / 12 / 12.5 / 13 / 14 / 17 / 20 共 12 档。建议收敛到 `Theme.Font` 五档：caption 11 / body 12.5 / callout 13 / title 14 / largeTitle 17/20。现在到处手写 `11.5`/`12.5` 微差，看着不规整。

4. **【建议】间距用 `Theme.Spacing`**：`Theme.Spacing` 已定义 8px 网格（xs4/sm8/md12/lg16/xl20/xxl24），但很多地方仍硬编码 `16`/`12`/`14`/`10`。统一引用常量，间距才稳。

5. **【可选】侧栏分组**：侧栏导航（4 个 tab）和底部工具链接（历史/反馈/macOS 工具）目前平铺，可加一个极轻的「工具」小标题或分隔，层级更清楚。改动小、收益低，可后置。

6. **【已合规，保持】**：风险语义色（用户数据橙 / 不确定黄 / 安全灰）三重编码、警示色复用橙、`keyboardShortcut(.cancelAction/.defaultAction)` 键盘可达性——这些都做对了，不动。
